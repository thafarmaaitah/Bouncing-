## Actual environment and input methods

WebKit **26.0** driven by Playwright **1.56.1**, in the official `mcr.microsoft.com/playwright:v1.56.1-noble` Linux container on a hosted GitHub runner. Browser graphics and game physics were actually executed. No Chrome test was substituted for a WebKit result.

Touch-enabled emulated viewports: phone 390x844 and 844x390; tablet 1024x650 and 768x1024. These are viewport sizes, NOT physical device models or iPadOS Safari executions.

Single-touch Start, Jump, Dash, Pause, Resume and menu actions used browser-driver taps. Simultaneous Forward+Jump, Forward+Dash and first-direction/second-Pause sequences used explicitly synthetic DOM PointerEvent objects (`pointerType=touch`, separate pointer IDs, `isTrusted=false`) delivered to the actual controls after hit testing. Real simulation snapshots verified movement, vertical motion, Dash/cooldown, release ownership, pause freezing and clean resume. This tests event-handler behavior in WebKit; it does NOT establish native multi-contact delivery, real pointer capture, hardware latency or physical iPad comfort.

Control probes only read state. Focused guide, win/loss and record tests use clearly marked test-only state fixtures inserted in local HTTP module responses. Those fixtures are absent from the published application. Character-transfer checks use a generated triangle GLB, NOT the private V4.1 girl.

## Covered behavior in both stages

- Actual engine/canvas boot, chosen goal and Practice/Time Challenge retention; control visibility and original tablet dimensions.
- Forward held with Jump and Dash; secondary action release preserves Forward; primary release clears held input. Synthetic multi-pointer method as described above.
- Pause while Forward is held clears keys and freezes actual position/time; native Resume advances time without unintended planar movement.
- Guide defaults off, opt-in marker appears without moving the player, moving-platform tracking, collapsed-target hiding and reverse direction toward a missing star.
- Three setbacks offer help without automatically enabling it or stopping gameplay.
- Once guided, turning the guide off mid-attempt cannot regain best-time, Clean run or Time finisher eligibility. Guided completion grants Explorer only. A fresh unassisted attempt restores normal eligibility; existing earned awards remain protected.
- Lava result -> Storm, correct goal/mode, identical synthetic model bytes and geometry; one-tap Replay, stage chooser, reload and End session semantics.
- Missing stars, game over and checkpoint retry; selective deletion preserves older-version record keys; malformed/external-resource model rejection does not upload data or remove the current model.

## Short owner check

Use the RC7 HUB in Safari on the actual iPad. Keep the approved original V4.1 GLB in Files on the device; it need not be uploaded to this chat or GitHub. The existing loader expects a self-contained GLB up to 20 MiB.

1. Select Lava and the original model once. Confirm unchanged appearance. From a safe central platform, hold movement while using Jump/Dash, then Pause with another finger. Release both fingers and Resume; unwanted movement must not continue.
2. Enable Show next platform for a guided attempt. Finish with five stars, confirm guided-result wording/no new unassisted record, and select Next: Storm Circuit. The same character should be restored without a second file selection in the same tab.
3. Test Storm's Replay. For an unassisted attempt use Restart, turn the guide off before Start. Report device/browser, whether V4.1 appeared and carried over, and the first failed step only. No child name or recording is needed.

Without the original local file, the controls and guide can be tested with the existing marker, but V4.1 acceptance remains open. Refreshing/ending the hub releases the in-memory character; existing saved badges remain subject to local browser storage availability.
